# Aguia Colportagem Compass

PROTÓTIPO DO SISTEMA ÁGUIA
## Controle e Acompanhamento da Colportagem

Quero uma reprodução EXTREMAMENTE FIEL, praticamente IDÊNTICA à imagem anexada.

A imagem anexada deve ser tratada como o modelo visual definitivo do projeto.

Reproduza com a máxima precisão possível:

- Mesma estrutura e organização dos elementos.
- Mesmas proporções e distribuição dos espaços.
- Mesmas cores e tonalidades.
- Mesmo estilo de sidebar.
- Mesmo formato, tamanho e posicionamento dos cards.
- Mesma hierarquia visual e tipografia.
- Mesmo estilo de gráficos, ícones, botões e indicadores.
- Mesmos detalhes de bordas, sombras, arredondamentos e espaçamentos.
- Mesma composição visual nas versões desktop e mobile.

**NÃO INVENTE OUTRO DESIGN. NÃO MODERNIZE. NÃO SIMPLIFIQUE. NÃO MUDE A IDENTIDADE VISUAL.**

A única adaptação permitida é substituir os textos, indicadores e informações demonstrativas pelos dados especificados neste prompt, preservando a estrutura visual original.

Quero olhar para o protótipo e reconhecer imediatamente a imagem de referência, como se fosse o mesmo projeto reproduzido em uma interface funcional.

## 2. OBJETIVO DO PROJETO

Desenvolver um protótipo visual do sistema **ÁGUIA — Controle e Acompanhamento da Colportagem**.

O sistema tem como objetivo permitir que os colportores registrem diariamente suas atividades, enquanto a liderança acompanha individualmente o desempenho de cada integrante e os resultados gerais da equipe.

O projeto terá duas interfaces:

- **Visão do Líder (Desktop):** painel administrativo para acompanhamento da equipe.
- **Visão do Colportor (Mobile):** interface para preenchimento diário das atividades.

## 3. DUAS VISÕES NO MESMO PROTÓTIPO

### VISÃO DO LÍDER — DESKTOP

Reproduzir fielmente a interface do computador apresentada na imagem.

O painel deverá apresentar:

- Visão geral da equipe.
- Indicadores de desempenho.
- Gráficos de desempenho.
- Últimos lançamentos dos colportores.
- Acesso aos colportores.
- Acesso aos lançamentos.
- Relatórios.

### VISÃO DO COLPORTOR — MOBILE

Reproduzir fielmente a interface do celular apresentada na imagem.

A interface deverá priorizar o preenchimento diário das atividades, mantendo a mesma organização visual, identidade e estilo da referência.

O preenchimento deverá ser simples, rápido e intuitivo.

## 4. ALTERNÂNCIA ENTRE AS VISÕES

Como este é um protótipo, preciso conseguir alternar entre a visão do líder e a visão do colportor.

Crie um seletor discreto, pequeno e pouco chamativo, que permita alternar entre:

- Líder
- Colportor

Esse seletor servirá exclusivamente para facilitar a apresentação e avaliação do protótipo.

Não deve interferir no design principal nem parecer uma funcionalidade central do sistema.

Ao selecionar uma opção, apresentar a respectiva interface:

- Líder: painel desktop.
- Colportor: interface mobile.

## 5. FUNCIONALIDADES — VISÃO DO COLPORTOR

Criar uma tela de lançamento diário com os seguintes campos:

### 5.1. Seguimento

Campo de seleção com duas opções:

- Casa em Casa
- Indicação

### 5.2. Ofertas

Campo numérico para registrar a quantidade de ofertas realizadas durante o dia.

### 5.3. Vendas

O registro de vendas deverá conter:

- Campo para informar o valor total vendido no dia.
- Seleção dos livros vendidos.
- Ao selecionar um livro, apresentar um controle de quantidade com botões (-) e (+).
- Permitir aumentar ou diminuir a quantidade de cada livro.

### 5.4. Orações

Campo numérico para registrar a quantidade de orações realizadas durante o dia.

### 5.5. Desafios

Campo de texto para o colportor descrever desafios, dificuldades ou necessidades encontradas durante o dia.

### 5.6. Horas Trabalhadas

Campo para informar a quantidade de horas trabalhadas durante o dia.

### 5.7. Salvar Lançamento

Adicionar um botão amarelo de destaque para salvar o lançamento diário, seguindo o estilo do botão apresentado na referência.

## 6. FUNCIONALIDADES — VISÃO DO LÍDER

### 6.1. Dashboard Inicial

Reproduzir a estrutura do dashboard apresentado na imagem, contendo:

- Indicadores gerais da equipe.
- Quantidade de ofertas.
- Quantidade de vendas.
- Quantidade de orações.
- Gráfico de desempenho.
- Últimos lançamentos realizados pelos colportores.

### 6.2. Colportores

Criar uma seção com a listagem dos colportores.

A liderança deverá conseguir visualizar os registros de cada colportor individualmente.

### 6.3. Lançamentos

Criar uma seção para visualizar os registros diários realizados pelos colportores.

### 6.4. Relatórios

Criar visualizações para os seguintes períodos:

- Diário.
- Semanal.
- Mensal.
- Semestral.

Os relatórios deverão permitir três formas de visualização:

**Individual por Colportor:**
Visualização dos registros e resultados de cada colportor individualmente.

**Por Seguimento:**
Visualização dos resultados separados entre:

- Casa em Casa.
- Indicação.

**Geral:**
Visualização dos resultados de toda a equipe.

Todos os relatórios serão de acesso exclusivo da liderança.

## 7. NOTIFICAÇÕES

Representar no protótipo a notificação diária por volta das 21h, lembrando o colportor de preencher seu lançamento.

## 8. IDENTIDADE VISUAL

Utilizar a identidade visual apresentada na imagem anexada:

- Azul-marinho como cor predominante.
- Amarelo como cor de destaque.
- Branco e tons claros para os fundos.
- Cards com cantos arredondados.
- Sombras suaves.
- Ícones consistentes.
- Tipografia semelhante à referência.

Manter a identidade visual rigorosamente consistente entre as duas interfaces.

## 9. ESCOPO DO PROTÓTIPO

Neste momento, desenvolver somente um protótipo visual navegável.

Não implementar:

- Backend.
- Banco de dados.
- Autenticação real.
- Integrações externas.

As interações básicas deverão funcionar para demonstrar:

- Alternância entre as duas visões.
- Navegação entre as telas.
- Seleção de seguimento.
- Seleção de livros.
- Controle de quantidade dos livros.
- Preenchimento dos campos.
- Botão de salvar lançamento.
- Filtros dos relatórios.

Utilize dados fictícios apenas para demonstrar visualmente o funcionamento.

## 10. ORIENTAÇÕES FINAIS

- Não invente funcionalidades ou campos além dos especificados.
- Não altere os nomes dos campos.
- Não complique a navegação.
- Não substitua a identidade visual por outra.
- Não transforme o projeto em um dashboard genérico.
- Preserve a estrutura original da imagem.
- Faça a interface desktop e mobile corresponderem às respectivas referências.

**RESULTADO ESPERADO:**

Um protótipo visual navegável do sistema ÁGUIA, com reprodução praticamente idêntica ao UI/UX da imagem anexada.
